# Terraform-Gesamtreflexion

## Lernpfad: Von Click-Ops zu GitOps

### T-01: IaC-Grundlagen
Wir haben verstanden, warum manuelle Infrastrukturverwaltung problematisch ist und wie IaC diese Probleme löst.

### T-02: HCL-Syntax
Die Grundlagen der HashiCorp Configuration Language und den Terraform-Workflow (init → plan → apply) erlernt.

### T-03: Variablen und Outputs
Konfigurationen flexibel und wiederverwendbar gemacht durch Variablen, Datentypen und Outputs.

### T-04: State Management
Die zentrale Bedeutung des Terraform State verstanden und Remote Backends mit Locking konfiguriert.

### T-05: Module
Wiederverwendbare Infrastruktur-Bausteine erstellt und das DRY-Prinzip auf Infrastruktur angewendet.

### T-06: Lifecycle Management
Zero-Downtime-Updates, Schutz kritischer Ressourcen und Provisioners für Post-Deployment-Aufgaben.

### T-07: Multi-Environment
Gleicher Code für Dev, Staging und Prod — nur die Konfiguration unterscheidet sich.

### T-08: CI/CD-Integration
Vollautomatisierte Pipeline: Lint → Security Scan → Plan → Review → Apply. Kein manuelles Apply mehr!

## NovaTech-Transformation
Von Toms manuellem Wochenend-Deployment mit der falschen Security Group zu einer vollautomatisierten, reviewten, gescannten und auditierbaren Infrastruktur-Pipeline. Das ist der Kern von Infrastructure as Code.
